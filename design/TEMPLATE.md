# 设计文档模板（TEMPLATE）

> 新建设计文档时复制本模板为起点。文件命名：`design/<分册>/<编号>-<英文短名>.md`；模块文档命名为 `M<NN>-<短名>.md`。
> 填写完成后删除所有 `>` 引用提示行。

```markdown
# <模块/主题名称> 设计

<一句话概述本模块/主题的职责与价值。>

## 版本记录

| 版本 | 日期       | 作者  | 变更说明               |
| ---- | ---------- | ----- | ---------------------- |
| v0.1 | 2026-08-29 | Maintainers | 初稿                   |
| v0.2 | 2026-08-30 | Codex | 模板改为功能稳定性与账号隔离边界 |

## 1. 概述与目标

- 解决什么问题、不解决什么问题（边界）
- 与 11 条原始需求（R01-R11）的映射

## 2. 功能清单

| 编号      | 功能             | 优先级 | 里程碑 | 说明                       |
| --------- | ---------------- | ------ | ------ | -------------------------- |
| Mxx-F001  | <功能名>         | P0     | MS1    | <验收口径，一句话>         |

> 编号规则：`M<两位模块号>-F<三位序号>`，全仓库唯一、只增不改不复用。
> 废弃功能不删除行，标记「已废弃」并在 checklist.json 同步状态为 `dropped`。

## 3. 流程图

Mermaid（GitHub 原生渲染）。状态机用 `stateDiagram-v2`，交互用 `sequenceDiagram`，分支逻辑用 `flowchart TD`。

## 4. 接口设计

TypeScript 签名（契约先行的载体）。只定义跨模块可见的接口；模块内部实现自由。

## 5. 数据模型

引用 `design/04-interfaces/data-models.md` 中的公共结构，只补充模块专属字段。

## 6. 配置设计

配置项、默认值、存放位置（profile `cordis.patch.yml` 的 `config:` 段）。

## 7. 依赖与边界

- 上层/下层依赖（分层规则见 02-principles）
- 复用档位：A 安装原版 / B 依赖集成 / C 功能参考（见 07-references）
- 平台属性：双端公用 / win 专属 / ubuntu 专属

## 8. 非功能与稳定性

性能、错误处理、超时取消、恢复、防误删，以及需要时的简单账号上下文隔离。

## 9. checklist 映射

列出本模块所有 F 编号，与 `checklist.json` 一一对应（校验脚本会检查双向一致）。

## 10. 开放问题

未定事项与后续决策记录；解决后移入对应章节并更新版本记录。
```

## 模板使用规则

1. **版本记录表必须存在**，每次修改文档都要追加一行，`scripts/validate-design.mjs` 会检查。
2. **F 编号三处一致**：模块文档 ↔ `checklist.json` ↔ `01-overview/trace-matrix.md`，脚本自动校验。
3. 新增需求走 `design/README.md` 的 SOP 流程，不要在旧章节里无痕修改。
